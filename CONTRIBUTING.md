# Contributing Guide

Welcome to the ACM Software Engineering Club! 👋

This guide explains how to contribute to our projects and how we manage issues, reviews, and collaboration.

## 1. Finding an Issue

You can browse the repository's open issues and choose an issue that you would like to work on.

- If an issue is **not assigned**, you can request to be assigned to it by commenting on the issue.

- Issue assignment follows a **First Come, First Served (FCFS)** approach.

- **Do not start working on an issue until it has been officially assigned to you.**

- If an issue is already assigned to someone else, please choose another issue or wait until it becomes available.

## 2. Progress & Assignment Policy

Once an issue is assigned to you, you are expected to make reasonable progress on it.

- You should share an update or progress within **one week** of being assigned.

- If there is no progress update for one week, the issue may be **unassigned** from you.

- This is done to give other contributors the opportunity to work on the issue.

- If you are facing a blocker, let the mentors know instead of leaving the issue without an update.

Progress can be shared through:

- A comment on the issue

- A draft PR

- A commit/branch update

- A discussion with the mentors

## 3. Communication & Mentorship

Don't hesitate to ask questions. We encourage contributors to communicate early rather than getting stuck.

> Asking questions is always welcome. There is no expectation that you should figure everything out alone.

## 4. Working on an Issue

Once an issue is assigned to you:

1. Understand the requirements of the issue.

2. Discuss any unclear requirements with the mentors.

3. Create a suitable branch for your work.

4. Implement the required changes.

5. Test your changes locally.

6. Open a Pull Request (PR).

7. Link the PR to the issue.

8. Wait for the review.

### Linking the PR to the Issue

Always link your PR to the issue it solves.

You can use GitHub keywords such as:

```text

Closes #123

```

or:

```text

Fixes #123

```

This allows GitHub to automatically associate the PR with the issue and close the issue when the PR is merged.

## 5. Pull Request Review

Every contribution must go through a review before it is merged.

The process is:

```text

Issue Assigned

      ↓

Development

      ↓

Pull Request

      ↓

CI Checks

      ↓

Code Review

      ↓

Apply Review Comments

      ↓

Approval

      ↓

Merge

```

During the review:

- Mentors/reviewers may leave comments or request changes.

- You should address all applicable review comments.

- Push your changes to the same branch so the PR is updated automatically.

- Once the required changes are completed and the PR is approved, it can be merged.

## 6. CI Requirements

Your PR must pass all required **CI checks** before it can be merged.

If a CI check fails:

- Check the failure logs.

- Fix the issue.

- Push the changes to your branch.

- Wait for CI to run again.

A PR should not be merged while required CI checks are failing.

## 7. Catch-up Meetings

We will have a **catch-up meeting every two weeks** to discuss the progress of the projects and contributors.

The meetings will be used to:

- Review what has been completed.

- Discuss ongoing issues.

- Identify blockers.

- Share progress between teams.

- Discuss upcoming tasks.

- Help contributors who are stuck.

Attendance and participation are encouraged so everyone stays aligned with the project.

## 8. General Guidelines

Please keep the following principles in mind:

- **Don't work on an issue until it is assigned to you.**

- Keep the issue updated with your progress.

- Ask for help when you need it.

- Communicate blockers as soon as possible.

- Keep PRs focused on the assigned issue.

- Follow the project's existing coding conventions.

- Make sure your changes pass CI before requesting approval.

- Respond to review comments and keep the discussion constructive.

- Help other contributors when you can.

We're building these projects together, so **communication, consistency, and helping each other are just as important as writing code.**

Happy contributing! 🚀
